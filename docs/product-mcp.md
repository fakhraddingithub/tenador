# اتصال MCP محصولات تنادور

آدرس MCP پس از انتشار: `https://YOUR-DOMAIN/api/mcp`

**اتصال از ChatGPT، کار در Codex.** حساب و OAuth از طریق افزونه/اتصال سفارشی ChatGPT تنظیم می‌شود (callback از chatgpt.com است) و Codex از همان اتصال استفاده می‌کند. خودِ ساخت و بازسازی محصول به زیرایجنت‌های بومی Codex نیاز دارد؛ در چت معمولی ChatGPT که زیرایجنت ندارد، گردش کار عمداً پیش از ذخیره متوقف می‌شود.

این سرور Streamable HTTP بدون نشست در همان برنامهٔ Next.js اجرا می‌شود و هیچ مدل یا workerی اجرا نمی‌کند. قواعد از `buildProductDraftPrompt` و تنظیمات زندهٔ پنل خوانده می‌شوند. جزئیات در [ایجنت‌های محصول](./product-jobs.md) آمده است.

شروع پروتکل و فهرست ساختار ابزارها بدون ورود قابل خواندن است تا ChatGPT ابزارها را بشناسد. تمام ابزارها OAuth می‌خواهند و فراخوانی بدون توکن، پیش از هر خواندن یا نوشتن داده، پاسخ `mcp/www_authenticate` برای نمایش پنجرهٔ اتصال می‌دهد. اتصال مجدد OAuth لزوماً تعریف ابزارهای ذخیره‌شده در افزونه را تازه نمی‌کند.

اگر ابزار جدید در چت دیده نمی‌شود، ابتدا پاسخ زندهٔ `tools/list` را بررسی کنید. سرور نسخهٔ `3.0.0` شامل `start_product_job`، `get_product_job`، `resume_product_job`، `validate_product_draft` و `review_product_draft` است و دیگر `prepare_product` ندارد. اگر سرور ابزار را دارد ولی افزونه ندارد، وضعیت اسکن/تعریف ابزار در مدیریت سازندهٔ افزونه را بررسی کنید. برای افزونه‌های منتشرشده در پورتال، مسیر مستندشده `MCPs → server → Issues → Rescan` است؛ ابزار تازه پس از عبور از بررسی‌ها در دسترس قرار می‌گیرد. رابط افزونهٔ سفارشی Development ممکن است متفاوت باشد؛ وجود دکمهٔ Refresh در صفحهٔ اتصال حساب را فرض نکنید. منبع: https://developers.openai.com/plugins/deploy/submission#scan-your-latest-changes

در اتصال مرورگر، لینک ورود باید `callbackUrl` همان درخواست اعتبارسنجی‌شدهٔ `/api/mcp/oauth/authorize` را نگه دارد. پس از ورود، کاربر به صفحهٔ رضایت بازمی‌گردد؛ ورود به‌تنهایی اجازهٔ دسترسی نیست. ورود گوگل هم با انتقال کامل صفحه به همین مسیر برمی‌گردد.

## راه‌اندازی

۱. متغیرهای زیر را در محیط سرور قرار دهید؛ هیچ‌کدام `NEXT_PUBLIC` نیستند:

```dotenv
MCP_PUBLIC_ORIGIN=https://YOUR-DOMAIN
MCP_CLIENT_ID=tenador-chatgpt
MCP_CLIENT_SECRET=GENERATE_A_LONG_RANDOM_SECRET
MCP_REDIRECT_URIS=EXACT_CALLBACK_URL_FROM_CHATGPT
```

برای ساخت secret از مدیر رمز یا `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` استفاده کنید. آن را در چت، مخزن یا ابزارهای محصول قرار ندهید. چند callback فقط با ویرگول جدا می‌شوند؛ wildcard مجاز نیست. آدرس callback را دقیقاً از صفحهٔ اتصال ChatGPT بگیرید، نه از مثال اینترنتی.

برای راه‌اندازی اولیه، `MCP_REDIRECT_URIS` می‌تواند خالی باشد: اطلاعات discovery در دسترس می‌ماند اما ورود OAuth تا ثبت callback دقیق مجاز نیست. پس از گرفتن callback آن را در متغیرهای محیط **سرور منتشرشده** قرار دهید و مجدداً deploy/restart کنید؛ تغییر `.env` محلی به‌تنهایی تنظیمات سایت منتشرشده را تغییر نمی‌دهد.

۲. MongoDB باید replica set باشد، مانند مسیر فعلی ساخت محصول. متغیرهای ImageKit سایت نیز باید تنظیم باشند. مدل‌های `McpGrant` (فقط توکن‌ها و کدهای OAuth) و `ProductPreparation` (آماده‌سازی‌های کار محصول) خودکار ثبت می‌شوند و اعتبار زمانی در هر درخواست بررسی می‌شود؛ علاوه بر آن TTL index رکوردهای منقضی را پاک می‌کند. در محیطی که autoIndex خاموش است، ایندکس‌های `key` (unique) و `expiresAt` (TTL صفر) هر دو مدل را در استقرار ایجاد کنید؛ `npm run ensure:indexes` هر دو را می‌سازد.

۳. برنامه را روی دامنهٔ HTTPS منتشر کنید. در ساخت اتصال سفارشی MCP در ChatGPT، آدرس بالا و OAuth را انتخاب کرده و Client ID و Client Secret را در فیلدهای تنظیم اتصال وارد کنید. این پیاده‌سازی از **کلاینت از پیش ثبت‌شده** استفاده می‌کند و endpoint ثبت پویای کلاینت ندارد. اگر صفحهٔ اتصال شما فیلد client credentials ندارد، باید از مسیر تنظیم اتصال با OAuth از پیش ثبت‌شده استفاده کنید؛ سرور را بدون احراز هویت منتشر نکنید.

۴. ابتدا با حساب ادمین در سایت وارد شوید، سپس از ChatGPT اتصال را شروع کنید. صفحهٔ رضایت تنادور، حساب و مقصد را نشان می‌دهد. تأیید، کد یک‌بارمصرف ۶۰ ثانیه‌ای با PKCE S256 صادر می‌کند. access token یک ساعت و refresh token سی روز اعتبار دارد. refresh می‌چرخد؛ لغو اتصال از endpoint revocation، خانوادهٔ توکن را باطل می‌کند. پس گرفتن عضویت یا مجوزهای ادمین نیز در درخواست بعدی اثر می‌گذارد.

۵. ادمین باید برای خواندن `products.view`، آماده‌سازی `ai.productDraft`، ساخت `products.create` و بازسازی `products.edit` داشته باشد. دسترسی OAuth فقط حوزهٔ محصولات را پوشش می‌دهد؛ ابزار سفارش، کاربر یا پرداخت ندارد.

مستند رسمی اتصال و احراز هویت: https://developers.openai.com/plugins/build/auth

## اتصال Claude Code

Claude Code یک کلاینت و یک endpoint جدا دارد، تا اتصال ChatGPT/Codex دست نخورد:

| | ChatGPT / Codex | Claude Code |
|---|---|---|
| endpoint | `/api/mcp` | `/api/mcp/native` |
| کلاینت | `MCP_CLIENT_ID` / `MCP_CLIENT_SECRET` | `MCP_NATIVE_CLIENT_ID` / `MCP_NATIVE_CLIENT_SECRET` |
| callback | `MCP_REDIRECT_URIS` (فقط HTTPS) | `MCP_NATIVE_REDIRECT_URIS` (فقط `http://localhost:PORT/...`) |
| بدون توکن | ابزارها دیده می‌شوند و فراخوانی، پنجرهٔ اتصال را باز می‌کند | پاسخ 401 که Claude Code را به ورود OAuth می‌برد |

توکن هر endpoint فقط روی همان endpoint کار می‌کند. تنظیمات `MCP_NATIVE_*` اختیاری‌اند؛ اگر نباشند یا اشتباه باشند فقط اتصال Claude Code غیرفعال می‌شود (یک هشدار در لاگ سرور) و اتصال ChatGPT/Codex کار می‌کند.

۱. در محیط سرور (Vercel) اضافه کنید و دوباره deploy کنید:

```dotenv
MCP_NATIVE_CLIENT_ID=tenador-claude-code
MCP_NATIVE_CLIENT_SECRET=GENERATE_ANOTHER_LONG_RANDOM_SECRET
MCP_NATIVE_REDIRECT_URIS=http://localhost:8765/callback
```

secret را مثل secret اصلی بسازید، ولی **همان را دوباره استفاده نکنید**. پورت دلخواه است ولی باید با `--callback-port` یکی باشد.

۲. در ترمینالی که Claude Code را اجرا می‌کنید (نام سرور باید `tenador` باشد، چون ایجنت‌ها با همین نام به ابزارها دسترسی دارند):

```bash
MCP_CLIENT_SECRET=<MCP_NATIVE_CLIENT_SECRET> claude mcp add --transport http tenador https://YOUR-DOMAIN/api/mcp/native --client-id tenador-claude-code --client-secret --callback-port 8765
```

۳. در Claude Code دستور `/mcp` را بزنید، `tenador` را انتخاب و Authenticate کنید. در مرورگر با حساب ادمین وارد شوید؛ صفحهٔ رضایت نام برنامه و مقصد `http://localhost:8765` را نشان می‌دهد.

۴. Claude Code را در همین مخزن باز کنید تا مهارت `.claude/skills/tenador-products` و چهار ایجنت `.claude/agents/tenador-*` را ببیند. در این ایجنت‌ها فقط متخصص کاتالوگ ابزارهای خواندنی تنادور را دارد و هیچ‌کدام نمی‌توانند ذخیره کنند؛ همهٔ تغییرات را جلسهٔ اصلی انجام می‌دهد.

فلگ‌های `--client-id`، `--client-secret` و `--callback-port` را پیش از استفاده با `claude mcp add --help` در نسخهٔ نصب‌شده تأیید کنید.

## استفاده

برای ساخت و بازسازی از ایجنت‌های بومی Codex و مهارت `tenador-products` استفاده کنید. `start_product_job` پرامپت کامل، منبع و `preparation.workflow` را برمی‌گرداند؛ همین workflow تنها نسخهٔ معتبر گردش کار است. `awaiting_chat` یعنی ادامهٔ کار با مدل داخل چت است. راهنمای کامل: [ایجنت‌های محصول](product-jobs.md).

نمونه درخواست:

> این محصول را از این لینک، با قوانین فعلی پنل تنادور بساز. دستهٔ مناسب را پیدا کن، متن فارسی و ویژگی‌ها را آماده کن و عکس‌های مربوط به همین محصول را هم منتقل کن. اگر قیمت یا مشخصهٔ ضروری معلوم نیست از من بپرس.

یا:

> محصول «نام محصول» را با این متن مرجع بازسازی کن. ابتدا تغییرات را نشان بده و تصاویر و واریانت‌های فعلی را نگه دار.

ترتیب ابزارها:

- `list_product_categories` / `search_products`: پیدا کردن دسته و محصول.
- `start_product_job` (و برای ادامه `get_product_job` / `resume_product_job`): متن یا URL مرجع، پرامپت جاری پنل و پیشنهاد عکس‌ها. آماده‌سازی مخصوص همان ادمین است و با هر استفاده یک ساعت تمدید می‌شود. تغییر قواعد پنل یا دسته آن را کهنه می‌کند؛ تغییر برند/ورزشکار/سری در جای دیگر سایت نه.
- `import_product_images`: حداکثر ۶ عکس در هر فراخوانی، حداکثر ۵ مگابایت برای هر فایل؛ نتیجهٔ هر عکس جداگانه گزارش می‌شود. URL خروجی ImageKit در JSON محصول قرار می‌گیرد.
- `validate_product_draft`: پیش از بازبینی، همان اعتبارسنجی ذخیره را بدون ثبت چیزی اجرا می‌کند و `fieldErrors` / `normalizedJson` برمی‌گرداند.
- `review_product_draft`: تأیید واقعی بازبین مستقل را به JSON دقیق متصل می‌کند؛ تغییر JSON بازبینی تازه لازم دارد. شناسهٔ ایجنت‌ها اظهارات میزبان است، نه اثبات مستقل سرور.
- `create_product`: ساخت **غیرفعال** با اعتبارسنجی سایت؛ برای انتشار از پنل ادمین استفاده کنید. اجرای مجدد همان کار محصول تکراری نمی‌سازد. اگر سرور وسط ساخت قطع شود، قبل از هر کار دیگری `get_product_job` و جستجوی محصول را انجام دهید.
- `preview_product_regeneration` سپس `apply_product_regeneration`: همان JSON و `updatedAt` پیش‌نمایش لازم است؛ تغییر هم‌زمان محصول رد می‌شود. تصاویر و واریانت‌ها دست‌نخورده می‌مانند.
- `replace_product_images`: جایگزینی اختیاری تصاویر محصول موجود، فقط با عکس‌های واردشده و نسخهٔ جاری محصول. پس از بازتولید، آماده‌سازی تازه و واردکردن عکس‌ها لازم است تا نسخهٔ تازه در دسترس باشد.

## محدودیت‌ها و نگهداری

- صفحات عمومی HTML و JSON-LD پشتیبانی می‌شوند. صفحات پشت ورود، ضدربات یا نیازمند اجرای JavaScript ممکن است خوانده نشوند؛ در این حالت متن مرجع و لینک مستقیم تصاویر را بدهید.
- عکس‌های استخراج‌شده «پیشنهاد» هستند؛ ChatGPT باید ارتباطشان با محصول را بررسی کند. فایل‌های JPEG/PNG/WebP/AVIF پذیرفته می‌شوند؛ SVG و PDF در این واردکننده پذیرفته نیستند.
- دانلود فقط HTTPS عمومی است؛ DNS به آدرس بررسی‌شده متصل می‌شود، شبکهٔ داخلی و loopback مسدودند، ریدایرکت‌ها دوباره بررسی می‌شوند و زمان/حجم محدود است.
- متن سایت مرجع دستور نیست. مدل باید قوانین پنل را اجرا کند؛ سرور ساختار، ارجاع‌ها و قواعد فیلدهای محصول را اعتبارسنجی می‌کند، اما اجرای معنایی تمام دستورهای متنی پنل را نمی‌توان با اعتبارسنجی ساختاری تضمین کرد.
- سهمیهٔ هر ادمین، مستقل از سایر دستیارهای سایت: ابزارهای خواندنی ۶۰ در دقیقه و ۱۰۰۰ در روز؛ نوشتن و دریافت از اینترنت ۲۰ در دقیقه و ۳۰۰ در روز.
- تصاویری که وارد شده‌اند ولی هیچ محصولی از آن‌ها استفاده نکرده، هر روز ساعت ۴ (UTC) با Vercel Cron و `GET /api/cron/product-images` (با `CRON_SECRET`) از ImageKit پاک می‌شوند: در کار ذخیره‌شده پس از انقضای آماده‌سازی‌اش، و در کار نیمه‌تمام پس از ۳۰ روز بدون تغییر. تصویری که محصولِ همان کار یا `mainImage`/`gallery` محصولی دیگر یا تصاویر واریانتی از آن استفاده می‌کند حفظ می‌شود؛ حذف ناموفق در اجرای بعد تکرار می‌شود. پیش از استفادهٔ عملی مطمئن شوید اجازهٔ استفاده از تصاویر مرجع را دارید.
- ثبت عملیات نوشتن به همان دامنهٔ ممیزی ادمین متصل است؛ خودِ محصول ممیزی می‌شود، ولی `McpGrant`، `ProductPreparation` و `ProductJob` (که متن منبع و پرامپت کامل را دارند) در لاگ ممیزی ثبت نمی‌شوند. شواهد بازبینی در `result.review` همان جاب می‌ماند. رکورد آماده‌سازی با هر استفاده یک ساعت تمدید می‌شود؛ جاب پایدار متن و پرامپت را برای ادامه نگه می‌دارد و TTL جاب را حذف نمی‌کند. توکن‌های OAuth به‌صورت hash ذخیره می‌شوند.
- برای غیرفعال‌سازی فوری کل اتصال، تنظیمات `MCP_*` را بردارید و مجدداً منتشر کنید. برای یک ادمین، عضویت/مجوز او را لغو کنید یا توکن‌هایش را از مجموعهٔ `mcpgrants` حذف کنید؛ این کار به آماده‌سازی‌ها و جاب‌های او دست نمی‌زند.

## بررسی

```bash
npm run test:mcp
npm run test:product-creation
npm run test:product-regeneration
```

تست MCP از MongoDB موقت و کلاینت واقعی SDK استفاده می‌کند و OAuth/PKCE، چرخش و لغو توکن، مجوز ابزار، استخراج مرجع، مسدودکردن آدرس داخلی، پرامپت پنل، ساخت غیرفعال، جلوگیری از تکرار، پیش‌نمایش/اعمال و endpoint HTTP را بررسی می‌کند. تست خودکار، اتصال واقعی حساب ChatGPT یا آپلود واقعی ImageKit نیست؛ بعد از استقرار یک محصول آزمایشی غیرفعال را سرتاسری بررسی کنید.
