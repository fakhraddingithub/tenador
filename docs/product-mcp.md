# اتصال محصولات تنادور به ChatGPT

آدرس MCP پس از انتشار: `https://YOUR-DOMAIN/api/mcp`

این سرور Streamable HTTP بدون نشست در همان برنامهٔ Next.js اجرا می‌شود. مسیر پیش‌فرض ساخت و بازسازی، کار پس‌زمینه با نویسنده و بازبین مستقل است؛ به کلید API مدل و worker نیاز دارد. راه‌اندازی و جزئیات در [تولید مرحله‌ای محصول](./product-jobs.md) آمده است. ابزارهای دستی قبلی نیز باقی مانده‌اند. قواعد هر دو مسیر از `buildProductDraftPrompt` و تنظیمات زندهٔ پنل خوانده می‌شوند.

شروع پروتکل و فهرست ساختار ابزارها بدون ورود قابل خواندن است تا ChatGPT ابزارها را بشناسد. تمام ابزارها OAuth می‌خواهند و فراخوانی بدون توکن، پیش از هر خواندن یا نوشتن داده، پاسخ `mcp/www_authenticate` برای نمایش پنجرهٔ اتصال می‌دهد. اتصال مجدد OAuth لزوماً تعریف ابزارهای ذخیره‌شده در افزونه را تازه نمی‌کند.

اگر ابزار جدید در چت دیده نمی‌شود، ابتدا پاسخ زندهٔ `tools/list` را بررسی کنید. سرور نسخهٔ `1.1.0` شامل `start_product_job`، `get_product_job` و `resume_product_job` است. اگر سرور ابزار را دارد ولی افزونه ندارد، وضعیت اسکن/تعریف ابزار در مدیریت سازندهٔ افزونه را بررسی کنید. برای افزونه‌های منتشرشده در پورتال، مسیر مستندشده `MCPs → server → Issues → Rescan` است؛ ابزار تازه پس از عبور از بررسی‌ها در دسترس قرار می‌گیرد. رابط افزونهٔ سفارشی Development ممکن است متفاوت باشد؛ وجود دکمهٔ Refresh در صفحهٔ اتصال حساب را فرض نکنید. منبع: https://developers.openai.com/plugins/deploy/submission#scan-your-latest-changes

در اتصال مرورگر، لینک ورود باید `callbackUrl` همان درخواست اعتبارسنجی‌شدهٔ `/api/mcp/oauth/authorize` را نگه دارد. پس از ورود، کاربر به صفحهٔ رضایت بازمی‌گردد؛ ورود به‌تنهایی اجازهٔ دسترسی نیست. ورود گوگل هم با انتقال کامل صفحه به همین مسیر برمی‌گردد.

## راه‌اندازی

۱. متغیرهای زیر را در محیط سرور قرار دهید؛ هیچ‌کدام `NEXT_PUBLIC` نیستند:

```dotenv
MCP_PUBLIC_ORIGIN=https://YOUR-DOMAIN
MCP_CLIENT_ID=tenador-chatgpt
MCP_CLIENT_SECRET=GENERATE_A_LONG_RANDOM_SECRET
MCP_REDIRECT_URIS=EXACT_CALLBACK_URL_FROM_CHATGPT
```

برای ساخت secret از مدیر رمز یا `node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"` استفاده کنید. آن را در چت، مخزن یا ابزارهای محصول قرار ندهید. چند callback فقط با ویرگول جدا می‌شوند؛ wildcard مجاز نیست. آدرس callback را دقیقاً از صفحهٔ اتصال ChatGPT بگیرید، نه از مثال اینترنتی.

برای راه‌اندازی اولیه، `MCP_REDIRECT_URIS` می‌تواند خالی باشد: اطلاعات discovery در دسترس می‌ماند اما ورود OAuth تا ثبت callback دقیق مجاز نیست. پس از گرفتن callback آن را در متغیرهای محیط **سرور منتشرشده** قرار دهید و مجدداً deploy/restart کنید؛ تغییر `.env` محلی به‌تنهایی تنظیمات سایت منتشرشده را تغییر نمی‌دهد.

۲. MongoDB باید replica set باشد، مانند مسیر فعلی ساخت محصول. متغیرهای ImageKit سایت نیز باید تنظیم باشند. مدل `McpGrant` خودکار ثبت می‌شود و اعتبار زمانی در هر درخواست بررسی می‌شود؛ علاوه بر آن TTL index رکوردهای منقضی را پاک می‌کند. در محیطی که autoIndex خاموش است، ایندکس‌های `key` (unique) و `expiresAt` (TTL صفر) را در استقرار ایجاد کنید.

۳. برنامه را روی دامنهٔ HTTPS منتشر کنید. در ساخت اتصال سفارشی MCP در ChatGPT، آدرس بالا و OAuth را انتخاب کرده و Client ID و Client Secret را در فیلدهای تنظیم اتصال وارد کنید. این پیاده‌سازی از **کلاینت از پیش ثبت‌شده** استفاده می‌کند و endpoint ثبت پویای کلاینت ندارد. اگر صفحهٔ اتصال شما فیلد client credentials ندارد، باید از مسیر تنظیم اتصال با OAuth از پیش ثبت‌شده استفاده کنید؛ سرور را بدون احراز هویت منتشر نکنید.

۴. ابتدا با حساب ادمین در سایت وارد شوید، سپس از ChatGPT اتصال را شروع کنید. صفحهٔ رضایت تنادور، حساب و مقصد را نشان می‌دهد. تأیید، کد یک‌بارمصرف ۶۰ ثانیه‌ای با PKCE S256 صادر می‌کند. access token یک ساعت و refresh token سی روز اعتبار دارد. refresh می‌چرخد؛ لغو اتصال از endpoint revocation، خانوادهٔ توکن را باطل می‌کند. پس گرفتن عضویت یا مجوزهای ادمین نیز در درخواست بعدی اثر می‌گذارد.

۵. ادمین باید برای خواندن `products.view`، آماده‌سازی `ai.productDraft`، ساخت `products.create` و بازسازی `products.edit` داشته باشد. دسترسی OAuth فقط حوزهٔ محصولات را پوشش می‌دهد؛ ابزار سفارش، کاربر یا پرداخت ندارد.

مستند رسمی اتصال و احراز هویت: https://developers.openai.com/plugins/build/auth

## استفاده

برای درخواست خودکار، `start_product_job` را با `requestKey` ثابت، دسته/محصول و متن/لینک مرجع اجرا کنید. نتیجه را با `get_product_job` پیگیری کنید. فقط `completed` به معنی ثبت است. سؤال‌های `needs_input` با پاسخ واقعی کاربر و `resume_product_job` ادامه پیدا می‌کنند. مراحل پایین مربوط به جریان دستی قبلی‌اند.

نمونه درخواست:

> این محصول را از این لینک، با قوانین فعلی پنل تنادور بساز. دستهٔ مناسب را پیدا کن، متن فارسی و ویژگی‌ها را آماده کن و عکس‌های مربوط به همین محصول را هم منتقل کن. اگر قیمت یا مشخصهٔ ضروری معلوم نیست از من بپرس.

یا:

> محصول «نام محصول» را با این متن مرجع بازسازی کن. ابتدا تغییرات را نشان بده و تصاویر و واریانت‌های فعلی را نگه دار.

ترتیب ابزارها:

- `list_product_categories` / `search_products`: پیدا کردن دسته و محصول.
- `prepare_product`: متن یا URL مرجع، پرامپت جاری پنل و پیشنهاد عکس‌ها. خروجی یک ساعت معتبر و مخصوص همان ادمین است. تغییر قواعد پنل ذخیرهٔ آماده‌سازی قدیمی را رد می‌کند.
- `import_product_images`: حداکثر ۶ عکس در هر فراخوانی، حداکثر ۵ مگابایت برای هر فایل؛ نتیجهٔ هر عکس جداگانه گزارش می‌شود. URL خروجی ImageKit در JSON محصول قرار می‌گیرد.
- `create_product`: ساخت **غیرفعال** با اعتبارسنجی سایت؛ برای انتشار از پنل ادمین استفاده کنید. اجرای مجدد همان آماده‌سازی محصول تکراری نمی‌سازد. اگر سرور وسط ساخت قطع شود، قبل از تکرار با آماده‌سازی تازه، محصول را جستجو کنید.
- `preview_product_regeneration` سپس `apply_product_regeneration`: همان JSON و `updatedAt` پیش‌نمایش لازم است؛ تغییر هم‌زمان محصول رد می‌شود. تصاویر و واریانت‌ها دست‌نخورده می‌مانند.
- `replace_product_images`: جایگزینی اختیاری تصاویر محصول موجود، فقط با عکس‌های واردشده و نسخهٔ جاری محصول. پس از بازتولید، آماده‌سازی تازه و واردکردن عکس‌ها لازم است تا نسخهٔ تازه در دسترس باشد.

## محدودیت‌ها و نگهداری

- صفحات عمومی HTML و JSON-LD پشتیبانی می‌شوند. صفحات پشت ورود، ضدربات یا نیازمند اجرای JavaScript ممکن است خوانده نشوند؛ در این حالت متن مرجع و لینک مستقیم تصاویر را بدهید.
- عکس‌های استخراج‌شده «پیشنهاد» هستند؛ ChatGPT باید ارتباطشان با محصول را بررسی کند. فایل‌های JPEG/PNG/WebP/AVIF پذیرفته می‌شوند؛ SVG و PDF در این واردکننده پذیرفته نیستند.
- دانلود فقط HTTPS عمومی است؛ DNS به آدرس بررسی‌شده متصل می‌شود، شبکهٔ داخلی و loopback مسدودند، ریدایرکت‌ها دوباره بررسی می‌شوند و زمان/حجم محدود است.
- متن سایت مرجع دستور نیست. مدل باید قوانین پنل را اجرا کند؛ سرور ساختار، ارجاع‌ها و قواعد فیلدهای محصول را اعتبارسنجی می‌کند، اما اجرای معنایی تمام دستورهای متنی پنل را نمی‌توان با اعتبارسنجی ساختاری تضمین کرد.
- محدودیت فعلی ابزارها برای هر ادمین ۱۰ فراخوانی در دقیقه و ۱۰۰ در روز است، مستقل از سهمیهٔ سایر دستیارهای سایت.
- فایل‌های موفقی که در نهایت به محصول وصل نشوند در ImageKit باقی می‌مانند. حذف خودکار انجام نمی‌شود؛ خطاهای هر تصویر را بررسی کنید. پیش از استفادهٔ عملی مطمئن شوید اجازهٔ استفاده از تصاویر مرجع را دارید.
- ثبت عملیات نوشتن به همان دامنهٔ ممیزی ادمین متصل است. رکورد آماده‌سازی متن مرجع را حداکثر یک ساعت نگه می‌دارد؛ توکن‌ها به‌صورت hash ذخیره می‌شوند.
- برای غیرفعال‌سازی فوری کل اتصال، تنظیمات `MCP_*` را بردارید و مجدداً منتشر کنید. برای یک ادمین، عضویت/مجوز او را لغو کنید یا توکن‌هایش را از مجموعهٔ `mcpgrants` حذف کنید.

## بررسی

```bash
npm run test:mcp
npm run test:product-creation
npm run test:product-regeneration
```

تست MCP از MongoDB موقت و کلاینت واقعی SDK استفاده می‌کند و OAuth/PKCE، چرخش و لغو توکن، مجوز ابزار، استخراج مرجع، مسدودکردن آدرس داخلی، پرامپت پنل، ساخت غیرفعال، جلوگیری از تکرار، پیش‌نمایش/اعمال و endpoint HTTP را بررسی می‌کند. تست خودکار، اتصال واقعی حساب ChatGPT یا آپلود واقعی ImageKit نیست؛ بعد از استقرار یک محصول آزمایشی غیرفعال را سرتاسری بررسی کنید.
