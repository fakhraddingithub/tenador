# مدیریت کیف پول و مبلغ پاداش نظر

## مجوزها

- `users.view`: مشاهده موجودی و ۵۰ تراکنش اخیر در صفحه کاربر؛ همان منبع تاریخچه داشبورد کاربر.
- `users.adjustWallet`: افزایش یا کاهش موجودی با مبلغ صحیح مثبت به تومان و توضیح الزامی تا ۵۰۰ نویسه. ویرایش پروفایل دیگر موجودی را تغییر نمی‌دهد؛ درخواست قدیمی `walletBalance` با خطای ۴۰۰ رد می‌شود.
- `comments.view`: مشاهده مبلغ محاسبه‌شده یا پاداش ثبت‌شده نظر.
- `comments.adjustReward`: تغییر مبلغ پاداش نظر واجد شرایط پیش از اولین تأیید، مستقل از مجوز تأیید نظر. این مجوز از مدیریت نقش‌ها/دسترسی ادمین قابل تخصیص است.
- `comments.moderate`: تأیید/رد و بررسی واریز طبق سازوکار قبلی.

API در هر درخواست از گیت عضویت فعال و دسترسی فعلی ادمین استفاده می‌کند. شناسه ادمین از نشست احراز هویت استخراج می‌شود و از بدنه درخواست پذیرفته نمی‌شود.

## تغییر موجودی

`POST /api/admin/users/:userId/wallet` فیلدهای `amount`, `type` (`credit` یا `debit`), `description`, `requestKey` را می‌گیرد. موجودی، دفتر تراکنش و رسید دائمی درخواست در یک تراکنش MongoDB نوشته می‌شوند. مبلغ نامعتبر، موجودی منفی، سرریز عدد و برداشت بیش از موجودی رد می‌شوند. در نبود پشتیبانی تراکنش هیچ تغییر مالی انجام نمی‌شود.

کلید درخواست برای همان ادمین و کاربر از اجرای تکراری جلوگیری می‌کند. تکرار همان کلید با اطلاعات متفاوت خطای ۴۰۹ دارد. رسید `WalletAdjustment` مستقل از تراکنش نمایشی باقی می‌ماند و نباید برای پاک‌سازی تاریخچه حذف شود. رابط کاربری پس از پاسخ نامطمئن کلید همان درخواست را برای تلاش مجدد نگه می‌دارد.

تراکنش شامل ادمین، موجودی پیش و پس از تغییر و توضیح است. توضیح در داشبورد کاربر نمایش داده می‌شود؛ اطلاعات داخلی ادمین و موجودی‌های میانی از API تاریخچه عمومی حذف شده‌اند. مدل‌های مالی در سامانه ثبت فعالیت ادمین نیز ثبت شده‌اند.

## پاداش نظر

`PATCH /api/admin/comments/:id/reward` مبلغ صحیح نامنفی به تومان می‌گیرد؛ صفر یعنی عدم پرداخت و `null` یعنی بازگشت به محاسبه خودکار. تغییر مبلغ، شروط خرید تأییدشده، وضعیت سفارش، نقش واجد شرایط، فعال بودن پاداش و جلوگیری از پرداخت تکراری را دور نمی‌زند.

بعد از اولین تأیید مبلغ قفل می‌شود؛ رد مجدد نظر آن را باز نمی‌کند. برای نظرهای قدیمی تأییدشده نیز ویرایش مجاز نیست. اطلاعات ویرایش پاداش در خواندن عمومی مدل انتخاب نمی‌شوند. هنگام تأیید از پنل، مبلغ نمایش‌داده‌شده با محاسبه سرور مقایسه می‌شود؛ اختلاف با خطای ۴۰۹ و بدون پرداخت/تأیید پاسخ داده می‌شود.

نیازی به انتقال موجودی یا مهاجرت پول نیست. داده‌های قدیمی با فیلدهای اختیاری جدید سازگارند. برای عملیات مالی MongoDB باید از تراکنش پشتیبانی کند.

## آزمون

`npm run test:admin-wallet` آزمون مالی روی replica set موقت و آزمون گیت API را اجرا می‌کند. `npm run test:review-credit` شامل مبلغ سفارشی، قفل پس از تأیید، مبلغ صفر، بازگشت به محاسبه خودکار و رقابت ویرایش با تأیید است. تست‌های کیف پول سفارش و مربی نیز باید هنگام تغییر سازوکار مالی اجرا شوند.
